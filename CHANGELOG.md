## [Unreleased]

### Audit

- The launcher's account, to the end: an audit is billed to the account that launched it and to no other, whoever resumes it and whatever account the desktop app, their session or the CLI's default uses by then; another account may read its files (the index, a monitoring pane), never run it. Before every launch of the audit session after the first (a relaunch after a failed preflight, an automatic resume after a usage limit, a scheduled or manual `--resume`), the launcher runs `account.py check "<folder>" "<email>"` on the folder and e-mail the register records. A folder logged out or logged in to another account (a `claude auth login` while the audit waited) stops the resume, with the register `suspended (account: …)`, the index saying the audit waits for its account, and the command that logs it back in; the same account found in another folder is used and the change of folder recorded. An `--in-session` audit records its session's e-mail and is checked with `account.py check --session`. Until now, an automatic resume relaunched on whatever account its folder held.
- `--account` is fixed at resume: given with `--resume`, it must be the e-mail the register records, or the resume stops.

- An audit stops itself when the desktop app deletes the session that launched it: only that session can stop the audit or decide how it ends (`closing.md`, 8.9), and until now a deleted launcher left the audit running in its own process, with nobody to stop it. The audit session's hook, `journal.py`, now takes `--launcher`, the launcher's transcript (`launch.md`, step 6); once the app has deleted that session (its transcript gone, `<session>.desktop-released.json` beside it with `"reason": "delete"`), the hook writes `stop-requested` itself, with that reason. The audit stops the usual way, each level reporting first, and records `suspended (launcher session deleted)`, for a `--resume` from another session. Closing the session, restarting the app or a CLI session leave no such marker, and the audit goes on.

### Tests

- `evals/account.sh` (no model): `account.py check` on simulated accounts.
- `evals/journal.sh`: a launcher session deleted stops the audit, with its own state; one still there, or released for another reason, stops nothing.

### Monitor

- `specaudit-monitor` (0.11.0), an optional plugin in `mods/specaudit-monitor/`, listed as a second plugin of the repository's marketplace (`/plugin install specaudit-monitor@spec-audit`): a band above the prompt (stage, progress, usage margin, the final figures once the audit has ended) and a detail pane (consumption, then progress, errors, evidence and technical details, folded by default). It reads the register, `SPECAUDITS.md`, git and the audit session's stream (`hooks/probe.py`), and never calls a model. It relies on Claude Code's mod API; `spec-audit` does not depend on it. Its tests: `claude plugin test mods/specaudit-monitor`.
- `specaudit-monitor` 0.12.0 follows an audit launched in another repository: `index.py` leaves a beacon, `~/.specaudit/beacon.json`, at each write of an index (best effort: a beacon that cannot be written changes neither the index nor the exit code, and without the monitor nothing reads it), and the monitor shows the beacon's repository when its audit is live, or newer than the current project's. Until now, an audit launched elsewhere, such as an end-to-end test's throwaway repository, did not show until the session changed folder.
- `specaudit-monitor` 0.13.0 pauses, stops and resumes the audit it shows, from three buttons in its band, each greyed when it cannot act: `⏸ pause` and `⏹ stop` while the audit runs in its own process, `▶ reprendre` once it is suspended. Pause and stop write `stop-requested` in that audit's scratch root (`closing.md`, 8.9); pause then tells the session that launched the audit to leave it suspended, and stop, confirmed by a second press within 10 s, asks that session to run `/spec-audit:stop`. Resume asks it for `/spec-audit:start <document> --resume`. The buttons act on the audit's own repository, also when it is the beacon's; a launch session that is not running gets a toast with the command instead. The band no longer draws bars: a spinner, turning every second, says the audit is working (`⏸` once it is suspended), beside its progress and usage margin as figures; the pane keeps its bars. An audit whose launcher was deleted shows as `Suspendu, session de lancement supprimée`.

## [1.0.0-beta.4] — 2026-10-13

### Project architecture

- `/spec-audit:init`, user-invoked: scans the files git tracks, reading only what it needs (folder names, READMEs, build files such as `lakefile.toml` and `lean-toolchain`, the markers of formal content, tables that look like a correspondence between results and formal names), and proposes the project's architecture: one role per path (`audited`, `original`, `prior-version`, `normative`, `sources`, `oracle` with its command, correspondence table and guard location, `ignored`), the profile of each audited document (`formal`, the only one, said so for anything else), and the mapped pairs, a document and its formal counterpart, which change together. It shows the proposal as a table, asks to accept, adjust or cancel, and only then writes `SPECAUDIT_ARCH.md` and offers to commit it alone; where no question can be asked, it prints the proposal and stops. Run again, it proposes the changes against the existing file. `skills/init/scan.py` does the scan.
- `/spec-audit:start` refuses to run without `SPECAUDIT_ARCH.md`, before anything is asked or created, and names `/spec-audit:init`; a document it is asked to audit must be `audited` in it.
- The audit follows the architecture: the oracle table is built from its `Oracles` rows instead of being discovered; reviewers and adjudicators receive the `normative` documents it gives; guards for an oracle go where its row says; and only the `audited` paths may be modified, with the audit's own corpus and records, and a mapped counterpart only together with its document. `skills/start/references/arch.py` holds this twice: a hook of the audit session refuses such an edit at once, and a check of the staged paths before every commit refuses it again; a refused change is restored and recorded as an error of the audit (`Architecture refusals` in the register, listed in the report). A fix that needs a read-only path is not made: the error stays confirmed, its fix proposed in the report.
- Reviewer isolation: reviewers and adjudicators may read `SPECAUDIT_ARCH.md`, which holds only what a referee could see in the repository, and must never read `SPECAUDITS.md`, the `SpecAudit-*/` folders, `spec-audit/`, the configuration, or the paths marked `original`, `prior-version` or `ignored`: said in `agents/*.md`, in a line that ends every message the orchestrator writes to them, and enforced in the audit session by the same hook.
- Orchestrator configuration: `.specaudit.md` or `.specaudit/config.md` keeps what only the orchestrator reads (version convention, defaults of the options, notes on scope and focus), `.specaudit/` the files the audit needs. Its keys `profiles` and `normative` moved to `SPECAUDIT_ARCH.md`; they are still read in this version, where the architecture says nothing, with a deprecation note, and init moves them.
- `docs/profiles.md`: step 3 of the roadmap, the profile proposed from the document's signals and written down once confirmed, is done, and generalized to the whole architecture.

### Audit

- One agent at a time: reviewers, adjudicators, probes and guard reviews run one after the other, in the foreground; the orchestrator launches one, waits for its result, then decides the next. Parallel agents saved no tokens, and raced on shared oracles (several `lake build` on one build directory), on texts being fixed and on files. In the audit session the hook (`references/journal.py`, `--lock`) makes every launch a foreground one and refuses a launch while an agent has not returned. A `--resume` has at most one unfinished agent to replace. Detection is unchanged in substance: every reviewer reads the whole document, fresh, without the others' results.
- Verification on a fresh state, one item at a time, roots before consequences: before verifying an item, its passage is reread at `HEAD` and re-quoted, or the item dropped (RESOLVED) when a fix already removed the defect (4.0, "Freshness"); every agent records the revision it ran on in the agent table, and every verdict its revision in the error's new `Verdicts` field, shown in the report's "Scope of verification"; a confirmed error is fixed, guarded and committed as an internal revision before the next item; and right after that commit, the inventory, `edges.json` and the cause graph are updated, and the use edges whose texts changed are probed again at once instead of at the next iteration. `discharge.py select` keeps the status of an edge already settled in the audit while its texts are unchanged (and a new status `refuted`), so that a re-probe touches only what the fix changed. `--fail-fast` follows the same loop.
- Each agent's revision is also written by the hook on its journal's launch line; the orchestrator takes `HEAD` from its last commit's output rather than a `git rev-parse` per launch, and keeps its own turns per item to four ("Context economy"): with one item at a time, its turns are what the audit's tokens grow with.
- `protocol.md` built by `references/protocol.py`, without the sections the orchestrator never or rarely needs (parameters, project configuration, closing, index format, manifest, corpus error entry, fail-fast and the Lean guard example when they do not apply), which go to `protocol/on-demand.md`: about 20 KB less sent with each of its turns.
- Options at resume: a `--resume` keeps the parameters its register records. Options given with it change them where that is allowed: `--max-passes`, `--auto`, `--keep`, `--pause-at`, `--no-auto-resume`, `--account`, `--uniform-effort` and `--no-discharge` freely; `--model` and `--model-version` flagged, the report saying which verdicts came from which model. The document, `--corpus`, `--base`, `--no-worktree`, `--in-session` and `--fail-fast` cannot change: a different value stops the resume. Every change is recorded in the register's `Parameters` history and listed in the report.
- The audit's branch is `audit/<stamp>`, the stamp of its results folder and index entry, reserved at launch (now step 3, before the worktree is created), instead of `audit/<slug>` with `-2`, `-3` suffixes. The worktree directory keeps its name.

### Closing

- The audit never merges its branch, nor proposes a merge or a pull request: "Accept and merge" is removed. It ends with a final commit on `audit/<stamp>` (document, corpus, register, report); the user merges it, or not, by their own means. The closing choices are "Keep the branch" (the default, and the non-interactive rule), "Run another check" and "Abandon". The results folder and the index entry still come back to the original branch, committed by path under the index lock, and name the branch and its final commit. The stop's "Keep the last revision as the new base" becomes "End at the last revision": a final commit on the branch, kept and not merged (index result `INTERRUPTED — ended at last revision`).

### Tests

- `evals/arch.sh` (no model): the proposal on a fixture project (`evals/_fixtures/arch-project/`: original manuscript and references, revised version and proofs, a Lean development with a correspondence table), the refusal without the file, the commit check and the hook. `evals/local-init.sh`: init run non-interactively on the fixture, and start refused without the file. New cases `init-proposes-architecture` and `start-refuses-without-arch`; `reviewer-ignores-session-history` gains an index lure.
- Every repository the cases and scripts build writes a minimal `SPECAUDIT_ARCH.md` first (`evals/_fixtures/write-arch.sh`).
- `evals/local-e2e.sh` checks, from the agents' journals, that no two agents overlapped (`_fixtures/serial_check.py`); that every agent and verdict revision is a commit of the audit's branch (`_fixtures/verdict_shas.py`); that the branch is `audit/<stamp>` with the results folder's stamp and ends with a final commit; and that nothing was merged into the original branch, which took only the results folder and the index, both naming the branch and its final commit. It also prints the wall-clock time and the audit session's tokens and cost.
- `evals/local-e2e-merge.sh` becomes `evals/local-e2e-no-merge.sh`: the closing without `--keep`, every error fixable, and no merge.
- `evals/local-e2e-parallel.sh` checks one branch `audit/<stamp>` per audit, agents one at a time in each, and no merge.
- `evals/journal.sh` tests the hook's one-agent lock on synthetic events, and `serial_check.py`.

### Fixed

- Audit billed to the wrong account: a session started from the Claude desktop app (or an Agent SDK host, or another `claude` session) hands its children its own credentials, a local proxy (`ANTHROPIC_BASE_URL` with `CLAUDE_CODE_ACCOUNT_UUID`…) or a token, which win over `CLAUDE_CONFIG_DIR`; the audit session was billed to the launcher's account whatever account the launch had settled, while `claude auth status` named the chosen one. `account.py clean-env` lists those variables, the audit session is launched under `env <clean-env>`, and `account.py list` reads the folders the same way. The eval scripts' account guard (`evals/_fixtures/account-guard.sh`) removes them too, so that a test started from the desktop app runs on the account it names.
- Results folder nested in itself: at a closing that keeps or abandons, the folder reserved at launch already exists, so copying the results folder onto it put them in `SpecAudit-<stamp>/SpecAudit-<stamp>/`, where the index's link and `replay.py` do not find them. `closing.md` now gives the copy of the contents (`cp -r "<worktree>/<folder>/." "<original repository>/<folder>/"`), and `index.py --add` refuses a results folder without `README.md` at its root, naming the nesting when it sees it.
- `journal.py --help` no longer waits on its standard input.

## [1.0.0-beta.3] — 2026-10-12

### Results

- Consumption in the report: a `## Consumption` section, between "Scope of verification" and "Branch and closing", with the tokens of the orchestrator and of each agent (reviewers, adjudicators, guard reviews, probes, named from their scratch directories), each one's share, the cost per model and in total as Claude Code reports it, and the audit's share of the account's session and week windows. The audit session writes the heading with one line; once its process has ended, the launcher measures every run's stream with `references/consumption.py` and puts the section in its place, before closing builds the results folder. Cache reads are counted in tokens but cost far less, so the share of tokens is not the share of cost; no cost per agent is computed; a window's share counts any other use of the account meanwhile, and a run during which the window reset has none. With `--in-session`, the section says consumption was not measured, there being no stream.
- Every run's stream kept: before each relaunch or `--resume`, the launcher moves `stream.jsonl` to `stream-<n>.jsonl`, and the consumption sums all of them.
- `SPECAUDITS.md`: a `Consumption` row in each audit's section (total tokens, cost, share of the week window).
- `evals/consumption.sh` tests `consumption.py` on synthetic streams; `local-e2e.sh` and `local-e2e-parallel.sh` check that each report's total is the one measured on its run's streams.

## [1.0.0-beta.2] — 2026-10-12

### Audit

- Stop from the bottom up: `/spec-audit:stop` writes a stop request instead of killing the audit session; its hooks refuse each agent's next tool call, so that the agent replies with its state (kept in `partial.md`, for the agent that resumes it), then the orchestrator's next launch, so that it records the stop and ends. The process is killed only if it has not ended within five minutes.
- Usage limits: the audit session's stream (`stream-json`) gives the account's usage of its session window and its week; above `--pause-at` (default 75 % of the session window and 50 % of the week), a hook of the audit session refuses the next agent's launch and the orchestrator stops, and the audit resumes from its last internal revision when the window resets: automatically for the session window, up to five times (`--no-auto-resume` to stop instead), by a confirmed scheduled task or by hand for the week. An agent journal, kept by hooks of the audit session (`references/journal.py`) rather than by the agents, which never kept their `progress.md`: each agent's prompt at launch (`prompt.md`), each of its tool calls with the start of its output (`journal.jsonl`), and its final reply (`result.md`); an agent stopped, killed or cut by a limit keeps its prompt and journal, and `--resume` relaunches only the agents without a result, with their prompt. `references/usage.py` reads the stream.
- Account confirmed at launch: the audit session runs `claude -p`, billed to the account the claude CLI is logged into, which may differ from the session's. The launch now lists the accounts of the configuration folders (`references/account.py`) and asks to continue with the current one, use another logged-in one, or run in the session, before anything is created; it can remember the choice for the project (`CLAUDE_CONFIG_DIR` in `.claude/settings.local.json`), and never logs in or out. `--account <email>` checks it instead of asking, and is required where no question can be asked. The account and its folder are recorded in the register and the report.
- `--fail-fast`: one detection wave, then the candidate errors confirmed from the most upstream, and a stop at the first confirmed error, without fixing it. The report gives the proposed fix of the statement and the results it may affect (direct uses, dependent results with their chains, results reached by a probe, main results first); the closing recommends keeping the worktree, or a full audit from there. For a first look at a document, or a beta test.
- `--max-passes N` replaces `--max-iter N`: the budget is the number of times the document is audited, fixed and audited again as fixed. `--max-iter`, and `max-iter` in the configuration's `defaults`, stay accepted as deprecated aliases.
- Hypothesis discharge: every use of a result by another is recorded with the hypotheses it relies on (`edges.json`), and each one the user does not visibly guarantee is probed at phase 1 by a fresh `spec-adjudicator`, which searches for an executed counterexample under the user's hypotheses. A red probe is a finding for triage, confirmed by another adjudicator; its counterexample is lifted to the results above, which join the cause graph as consequences at once. Settled probes are cached in the corpus (`discharge.json`), keyed on the texts of each edge, so that the next audit probes only what changed. `--no-discharge` turns it off. Design: `docs/hypothesis-discharge.md`.

### Fixed

- Windows launch: the audit session's allow list, launch command and register use native paths (`C:/…`, from `cygpath -m`), not the MSYS paths of Git Bash, which the session never matches, so that the preflight passes at its first attempt.
- Interpreter: phase 0 keeps `python3` only if it prints a Python 3 version, else `python` (on Windows, `python3` may be the Microsoft Store stub), records it in the register (`Interpreter`), and the protocol and the agents use that one instead of a hard-coded `python3`.
- Local end-to-end scripts (`evals/local-e2e*.sh`): one interpreter chosen the same way, and `$TEMP` normalized with `cygpath -m` where available, so that their checks no longer fail on Windows for environment reasons.
- Index written by concurrent audits: every write of `SPECAUDITS.md` (launch, closing, stop, failure, `/spec-audit:attest --update`) is one step under a lock, an empty `SPECAUDITS.md.lock` folder next to the index (outside `.git/`, which a `dontAsk` session may not write), re-reads the file under it, changes only the audit's own entry, found by its identifier rather than its position or its `RUNNING` result, and checks afterwards that every other entry is still there. Two audits launched side by side could erase each other's entry, or one could mark the other's as finished.
- Index written by a script: two end-to-end runs still showed one audit's launch erasing another's entry, the read and the write chained in one command and the lock released before the commit. `references/index.py` now does every write of `SPECAUDITS.md` in order, under the lock: read or create, replace or insert the audit's entry newest first, check every other entry unchanged, commit, unlock. Closing also sets the `Attested` cell to `no` by name.
- Session id: the register's `Session` line recorded the text `${CLAUDE_SESSION_ID}`, since `launch.md` is read rather than loaded and the variable is not filled in there; the id now comes from `SKILL.md`, where it is.
- Waiting for the audit session: an empty output no longer counts as an end (`claude -p` writes only when it finishes); only the process id does, and the launcher never relaunches while it is alive. A second session launched beside a running one had corrupted the register and the preflight count. The process and session ids are recorded as soon as the session starts.
- Absolute paths: every script path in a command is absolute, and the lint's command is recorded in the register, so that "run the lint" copies it instead of retyping a relative path the allow list refuses.

## [1.0.0-beta.1] — 2026-10-11

First public beta, of the `formal` profile: proofs, algorithms, protocol and format specifications.

### Audit

- Cold detection by fresh `spec-reviewer` agents, in waves until a wave brings nothing new; each candidate error refuted or confirmed by a fresh `spec-adjudicator` with an executed counterexample, on the strongest oracle of the project (mechanized development, reference model, or its own script), with its evidence level.
- Cause graph: errors fixed bottom-up, consequences blocked until their cause is fixed, suspects reassessed against the fixed text, causal loops stopping the audit.
- Regression guards seen red before each fix, including a text guard that reads the document itself; a suspect guard judged by a fresh adjudicator, never edited by the orchestrator (corpus errors).
- Minimal, traced fixes; critical fixes wait for the user unless `--auto`; a separate editorial track with a mechanical lint.
- The audit runs in a dedicated `claude -p` session in its own git worktree, with a preflight of every tool, a closed list of command forms and every refusal recorded; `--in-session` keeps it in the user's session.
- Effort set per step, with escalation on observable signals; the protocol loaded in parts, and a one-line digest per settled error, so that long audits stay affordable.
- Stop at any time with `/spec-audit:stop`; resume with `--resume`.

### Results

- A report ending with a summary of issues by priority, each with its mitigation and an effort range when something supports one.
- A self-contained results folder `SpecAudit-<YYYYmmdd_HHmmss>/` for every audit run to completion: sources as they were, report and annexes, the fixed document when no error stays open, and a corpus that replays on either version with Python alone.
- An index `SPECAUDITS.md` with an entry for every audit launched, from its launch (`RUNNING`) to its result, linked to a section that summarizes it.
- `/spec-audit:attest` checks the signed git tag with which a person stands by a result; the audit never signs.

### Project

- Audit profiles: the domain-specific rules in `skills/start/profiles/formal.md`; project configuration (`.specaudit.md` or `.specaudit/`) mapping documents to profiles, with project extensions of a profile.
- Folders as audit targets.
- Demo: a bubble sort specification with planted errors (`examples/demo/`), and the results of two real audits of it (`examples/demo-result/`).
- Beta testing: installation, first test, what to test and how to report, in the README, with an issue form for beta reports.
- Eval suite (`claude plugin eval`) and end-to-end scripts for the audit session, parallel audits, the "Accept and merge" closing, folder targets and attestation.
