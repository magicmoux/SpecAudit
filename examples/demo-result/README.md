# Results of two audits of the demo

What `/spec-audit:start` left after auditing [`../demo/bubble-sort.md`](../demo/bubble-sort.md), copied as files: for each run, the project's index `SPECAUDITS.md` and the results folder `SpecAudit-<stamp>/` it links. They spoil the exercise: run the demo yourself first if you want to see what the audit finds on its own ([../README.md](../README.md)).

| Run | Options | Outcome |
|---|---|---|
| [partial/](partial/SPECAUDITS.md) | `--max-iter 1 --keep` | FINISHED — Partial, needs decision, 5 / 3 errors confirmed / fixed; the fix of the abstract and the conclusion changes what the document claims, so it waits for a person: the fixes made are in `resources/corrections.patch` and `resources/bubble-sort.partial.md` |
| [complete/](complete/SPECAUDITS.md) | `--auto --max-iter 2 --keep` | FINISHED — Partial, to continue, 5 / 5 errors confirmed / fixed; critical fixes applied under `--auto`: `bubble-sort.fixed.md` beside `source/bubble-sort.md` |

Start with each folder's `README.md`, then `report.md`. The checks replay with Python alone, from a results folder: `python3 resources/replay.py --on source` shows each fixed error's guard red on the original, `--on fixed` every guard green on the complete run (on the partial one, the lint can stay red: form defects wait behind the pending fix).

Generated by `evals/snapshot-demo.sh` with the protocol of spec-audit 1.0.0-beta.1, model sonnet, on 2026-10-11. The runs used a throwaway repository and the git identity "SpecAudit demo"; paths of the machine that ran them are replaced by `<repo>` (the throwaway repository), `<tmp>` and `~`, and session identifiers by `<session>`. The worktree, the branch and the commits they name do not exist here. An audit is not deterministic: a new run finds the same planted errors, but may word them, order them or fix them differently. When the protocol changes, regenerate this folder rather than edit it.
